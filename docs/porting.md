# E1002 firmware status

Fil-C is excluded. Userspace is conventional C/C++; correct programs are assumed. NOMMU has no per-process address-space isolation, so this does not protect other processes from a faulty pointer or stack exhaustion.

`nix run .#build-firmware -- .work` builds the pinned Xtensa FDPIC SDK and target Skarnet packages, then evaluates the complete sixos site and host in `nix/sixos-site.nix`. Upstream `mkConfiguration` produces the service sources, compiled database, identity files, boot layout and target action scripts. The assembler copies the resulting Nix runtime closure into XIP cramfs, verifies target ELF loaders, libraries, script interpreters and store references, checks partition limits, and merges the upstream ESP32-S3 flash layout. No flash command is run.

The build deliberately keeps the known upstream 16MB map while the E1002 specifies 32MB. The kernel's MTD table and network adapter partition offsets must be changed together before using the additional flash. A merged binary that passes static checks is not proof that this board boots it.

`nix run .#test-emulator -- IMAGE.bin` runs the image under Espressif `esp-emu` 0.51.0 with an ESP32-S3 and 8MB PSRAM, then requires a Linux kernel banner on UART0. `esp-emu` does not provide the virtual access point and BLE stub the image's network adapter waits for, so it stops at `net80211 rom version` without loading Linux. Under `esp32sim` with `--wifi` and a `nimble_port_init` stub the image boots end to end: the kernel starts, the sixos CPIO stage one runs `rc.init`, `s6-rc-init` links the compiled database, the default bundle starts, and a UART `login:` prompt appears on UART0. Neither emulator models the reTerminal peripherals, so the board work below is still untested.

Bring-up needed these target fixes, all applied by the build rather than by hand-editing upstream sources:

1. skalibs' selfpipe uses `signalfd`, which this kernel does not implement; the target build forces the pipe fallback (`--with-sysdep-signalfd=no`).
2. The kernel mounts devtmpfs on `/dev` itself, so sixos stage one must not pass `-d /dev` (`devtmpfs-mountpoint = null`), which previously failed with `Device or resource busy`.
3. `s6-svscan` reserves about 260 KiB of stack for its default 1000-service/251-byte-name tables, overflowing the original 64 KiB NOMMU stack; it is wrapped with `-C 32 -L 48`. The Skarnet ELF stack reservation is now 32 KiB, reducing the contiguous allocations needed on 8 MiB PSRAM.
4. The kernel rejects file-backed `mmap` with `ENODEV`, so skalibs' `cdb_init_fromfd` falls back to an anonymous mapping filled by `read()`.
5. An infinite relative `tain` deadline does not fit in 32-bit `time_t`; `pthread_mutex_tailock` treated that `EOVERFLOW` as a failure and broke every `s6-svlisten`/ftrigr subscription, so it now takes the blocking lock instead.
6. `s6-rc` executes oneshot `up` files as execline, so sixos invokes the board shell scripts through `/usr/bin/dash`.
7. Runtime helpers `s6-ftrigrd`, `s6-svlisten`, `s6-svlisten1`, `s6-svwait`, and `s6-sudoc` are installed; without them `s6-rc-init` and oneshot activation fail with `ENOENT`.

The old shutdown-daemon restart loop was caused by the repacked CPIO containing regular files in place of FIFOs. `tools/init-cpio.py` now clears privileged mode bits only during sandbox extraction and restores their original archive metadata during repacking. The pipes remain real FIFOs, their types are checked, and normal sixos catch-all logging is enabled. Stage-one shutdown and runlevel scripts use the same system profile as activation.

The configuration is a real Nix derivation named `six-system-reterminal-e1002-*`, with separate store objects for its userspace, s6 runtime, service sources and compiled database. The image copies `nix-store --query --requisites` of that derivation; it does not manufacture a single store-looking directory or rewrite its hash. The system profile points to this configuration. `/bin`, `/usr` and `/lib` link into the pinned target userspace package, and `/sbin/init` is the sixos archive-unpacking entry point. Unused compilers, development programs and libcurl are omitted to fit the 7.5 MiB rootfs partition.

The Xtensa adapter extends sixos' CPU inspection with the actual 32-bit little-endian Xtensa/FDPIC target. Nixpkgs still lacks a general Xtensa cross package set, so target binaries come from the pinned external SDK build. Native builders remain ordinary nixpkgs packages. The native s6-rc compiler reads Xtensa configuration headers when generating service scripts; no native executable is shipped. Evaluation dependencies are hash-pinned in `nix/sixos-upstream.nix`. The pinned sixos revision's type schema predates its `boot.rootfs` attribute set and does not export a site validator, so its optional Yants validation is disabled; upstream host attribute-name and graph checks still run.

The immutable-flash adapter retains sixos' configuration output and replaces its activation/deployment entry points with an embedded activation script. Initial activation initializes the live s6-rc state and starts `default`; repeat activation reasserts `default` idempotently. Live database replacement triggered a fault in the pinned NOMMU kernel during testing, so configuration upgrades use flashing and reboot rather than `s6-rc-update`. The target has no Nix daemon, on-device profile deployment, doas installation or kexec. Images are built and deployed from the host. Network daemons stay disabled by default. The fake-clock services restore on boot and save on shutdown without an additional periodic process. Generated sixos passwd/group files seed writable `/etc` copies atomically, while hosts/hostname are linked to the configuration. BusyBox passwd needs writable account files for first-login provisioning. Root uses the existing JFFS2 shadow hash and upstream `user-shell` first-login flow.

Software verification on 2026-10-31: the complete build entry point was exercised with the existing pinned SDK, and the final configuration was reassembled after the lifecycle fixes. The image contains 115 validated Xtensa ELFs; its rootfs is 7,045,120 bytes within the 7,864,320-byte partition. `SIXOS_TEST_LIFECYCLE=1 tools/test-sixos.sh` verified first-login password provisioning, root identity, idempotent activation, all services stopping successfully, clock saving, and software reset without kernel faults or allocation failures. `nix flake check`, Nix formatting checks and shell/Python syntax checks pass. Hardware shutdown and persistence remain untested.

The E1002 schematic identifies GPIO3/4/5 as buttons, GPIO6 as the green LED, GPIO45 as buzzer enable, GPIO7/8/9 as display SPI, GPIO10/11/12/13 as display CS/DC/reset/busy, GPIO19/20 as I2C0 SDA/SCL, GPIO39/40 as I2C1, GPIO1 as battery ADC, and GPIO14/15/16 as the SD interface. The expansion header is GPIO46, GPIO2, GPIO17, GPIO18, GPIO20 and GPIO19. The current kernel tree has ESP32 GPIO, I2C and SPI support, but the board-specific panel, button, sensor, SD, charging and sleep integration still needs device-tree configuration and hardware testing. The earlier placeholder service scripts were removed.
