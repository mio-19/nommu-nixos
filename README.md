# nommu-nixos

Nix build workspace for Linux on ESP32-S3, with the real sixos s6-linux-init stage-one builder adapted to a fixed root filesystem. Userspace is conventional C/C++; Fil-C is excluded and correct programs are assumed.

The workspace can build the Xtensa FDPIC toolchain, compile the sixos s6 stack against the upstream `libfork` runtime, validate the root filesystem, and assemble an experimental 16MB image. It retains the upstream devkit's bootloader, Wi-Fi adapter, kernel, and flash offsets. The reTerminal E1002 has 32MB flash and different board peripherals, so this image still needs E1002 bring-up and serial validation before use.

```sh
nix build                         # porting kit and pinned source manifest
nix build .#upstream-reference    # upstream 16MB devkit image
nix flake check                  # layout checks
nix develop                     # host tools and source paths
nix run .#build-firmware -- .work # toolchain, target stack, and image
nix run .#test-emulator -- .work/firmware/reterminal-e1002-six-init-experimental.bin
```

The full build uses rootless Podman to build the upstream toolchain, then cross-compiles skalibs, execline, s6, s6-rc, and s6-linux-init. The resulting image is in `.work/firmware/`. To fit the upstream 7.5 MiB rootfs partition, the image omits upstream development utilities such as MicroPython, `make`, `nano`, `curl`, and `socat`. The completed target tree is added to the local Nix store with `nix store add`, and the returned real content-addressed path is copied into the image as `/nix/store/<hash>-reterminal-sixos-system`. `/bin`, `/sbin`, and `/usr` are symlinks to that store object for compatibility with the upstream kernel and scripts. It uses sixos' actual stage-one CPIO init builder and activation handoff; the minimal boot services are generated by sixos' `mkOneshot`, `mkService`, and `mkBundle` constructors. The sixos service database is compiled with the host s6-rc compiler. This is not yet a full sixos `mkSite`/`mkConfiguration` evaluated system, and does not support the ePaper panel, sensors, buttons, battery management, or sleep mode.

The artifact is experimental and untested on hardware. It retains upstream 16MB flash mappings despite the E1002's 32MB chip. NOMMU also does not isolate process memory; assuming correct programs does not add address-space protection. See [porting notes](docs/porting.md).

The flake pins Espressif's `esp-emu` 0.51.0 for local ESP32-S3 smoke tests. The test waits for the Linux kernel banner and saves UART output under `.work/`. The custom image currently reaches ROM and early ESP-IDF output but times out before a Linux banner; an upstream reference run watchdog-resets before Linux output. The emulator has not validated this Linux port.

Sources: [Linux-on-esp32-S3](https://github.com/paulneja/Linux-on-esp32-S3), [sixos](https://codeberg.org/amjoseph/sixos), [reTerminal E1002 schematic](https://files.seeedstudio.com/wiki/reterminal_e10xx/res/202004321_reTerminal_E1002_V1_2_SCH_251120.pdf), [Seeed E1002 guide](https://wiki.seeedstudio.com/getting_started_with_reterminal_e1002/).
